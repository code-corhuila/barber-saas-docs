# ADR-010 — Data Conventions per Domain: UUID Identifiers, Money in Cents, No Cross-Domain Foreign Keys

- **ID:** ADR-010
- **Date:** 2026-09-28
- **Status:** Accepted
- **Authors:** Carlos Mauricio Leal Medina, Daniel Felipe Cerquera Idrobo, Juan Pablo Borrero Morales, Carolay Arraut Heredia

---

## Context

The teacher's tracker (2026-09-28) rated the 07↔06 consistency red: the contracts in
`07-api/contracts/openapi/` use UUID identifiers and money in cents, while `06-data/models.md`
declared `BIGINT AUTO_INCREMENT` ids, `DECIMAL(10,2)` money, MySQL `ENUM` states and foreign keys
between every table. Both cannot be true at the same time.

`06-data/models.md` was a faithful transcription of the prototype's `init.sql` (category A, MySQL 8,
one shared schema). ADR-004 replaced that topology with one database per domain, and ADR-006 chose
PostgreSQL for seven domains and MongoDB for notifications. The course norm fixes the rest:
identifiers are UUID and money is an integer in minor units (5.3.5), states use `CHECK` and never
`ENUM`, text is `text` with a length `CHECK`, and money is `bigint` (5.2.5, annex A), and no foreign
key crosses domains (7.4).

---

## Decision

**We decided:** every domain database follows these conventions, and the contracts in `07-api` are
the reference the tables must match.

| Aspect | Convention |
|---|---|
| Identifiers | `uuid` primary key, generated by the service's domain core (not by a database sequence). In MongoDB, `_id` holds the UUID as a string |
| Money | `bigint` column with suffix `_cents`, `CHECK (… >= 0)`. Amounts are Colombian pesos × 100 (35,000 COP → `3500000`) |
| Quantities that are not money | `numeric(12,2)` (e.g. inventory stock in millilitres); never floating point |
| States and closed sets | `text` + named `CHECK` (`chk_<table>_<column>`), values equal to the contract enums |
| Text | `text` + `CHECK (char_length(…) <= n)` where the contract declares `maxLength` |
| Dates and times | `timestamptz` stored in UTC; calendar dates as `date`, times of day as `time` |
| Names | Singular `snake_case` tables, one schema named after the domain, nothing in `public` |
| Constraints and indexes | Explicit names `pk_`, `fk_`, `chk_`, `uq_`, `idx_`; every foreign key has an index |
| Reference to another domain | A `uuid` column with **no** foreign key, checked through that domain's contract |
| Tenant | `barbershop_id uuid NOT NULL` on every tenant-scoped table, filled from the token |
| Idempotent creation | One `idempotency_key` table per domain that creates resources over HTTP (norm 5.3.8) |
| Events | One `outbox_event` table per domain that publishes events (norm 5.3.11) |
| Audit | `created_at`, `updated_at` and `created_by` where the contract exposes `AuditFields` |

---

## Evaluated alternatives (options)

| Alternative | Pros | Cons | Reason for discarding |
|---|---|---|---|
| **UUID + cents + no cross-domain FK (chosen)** | Matches the norm and the contracts already merged; ids can be created before the row exists (idempotency, sagas) | 16-byte keys; the prototype's data and seeds must be converted | — (chosen) |
| Keep `BIGINT` ids and `DECIMAL` money in 06, change 07 | No conversion of the prototype | Breaks norm 5.3.5; sequential ids leak tenant volume and collide across eight databases | Not allowed by the norm |
| UUID in the API, `BIGINT` inside each database with a mapping column | Smaller internal keys | Two identities per row, a mapping to maintain, bugs where the wrong one leaks | Complexity with no benefit at this scale |

---

## Dominant criterion

**One truth between contract and table:** a field the API exposes must exist in its domain's table
with the same name (camelCase ↔ snake_case), type and set of values.

## Accepted cost

Every prototype table and seed is rewritten, not copied; money values are multiplied by 100;
references that used to be joins become calls to another service.

---

## Consequences

- `06-data/models.md` is rewritten per domain under these conventions. The prototype schema is kept
  as `06-data/prototype-schema.md`, marked historical, because it is the source of the business
  rules being ported.
- Contract fields still using floating point (`priceAtBooking` in `appointment-service.yaml`) move to
  `…Cents`.
- Every `-db` repository applies this table in its changesets (annexes A and B).
